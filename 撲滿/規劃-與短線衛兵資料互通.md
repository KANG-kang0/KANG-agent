# 規劃：零錢種子 × 短線衛兵 資料互通

> 2026-07-07 與使用者定案：**資料互通、產品分開**。不合併成一個產品。

## 定位分工（為什麼不合併）

- **零錢種子（撲滿）**：管「買什麼」——波段（1–3 月）選股、回測、進出提醒。使用者：自己。
- **短線衛兵**：管「現在危不危險」——個股體檢、風控快報。使用者：爸爸＋自己。
- 兩者節奏（波段 vs 短線）與使用者不同，合併會互相牽制；共用的只有「同一份清單與持倉」這個事實，用資料層解決就好。

## 互通機制（站在既有設施上，不要另起爐灶）

零錢種子已有 Supabase（見 `自動化撲滿/supabase-schema.sql`）：
- `positions`（持倉，RLS 限本人）
- 每日精選/個股統計表（**公開讀**、service_role 寫）
- `自動化撲滿/cloud_sync.py` 已在做 REST 同步

做法：短線衛兵 Worker 的風控掃描（見 [短線衛兵-worker/規劃-風控版面.md](../短線衛兵-worker/規劃-風控版面.md)）直接用 Supabase REST 讀零錢種子的資料：
1. 公開讀的表（每日精選）→ 用 anon key 讀即可。
2. `positions`（RLS 限本人）→ 把 service_role key 用 `wrangler secret put SEED_SUPABASE_KEY` 存進短線衛兵 Worker（**絕不寫進程式碼或 vars**），單向唯讀使用。
3. 短線衛兵**只讀不寫**零錢種子的表——寫入權留在零錢種子後端，避免兩邊搶真相。

## 給動手的 session 的前置功課

1. 先讀 `自動化撲滿/supabase-schema.sql` 全文與 `cloud_sync.py`，確認表名與欄位（本檔只列到 2026-07-07 的狀態，可能已漂移）。
2. 零錢種子的 Supabase 專案與小書蟲的是**不同專案**，URL 在 `自動化撲滿/config.py`（該檔不在 KANG-agent 版控內）。
3. 觀察清單目前在 `watchlist.txt`（本機檔）——若要讓短線衛兵讀到，得先加一張 `watchlist` 表＋讓零錢種子同步上去，這是本整合的第一個實作項目。
4. 撲滿子目錄是獨立 git repo：改 `自動化撲滿/` 裡的東西要在該目錄內 commit/push，不是 KANG-agent。

## 順序

風控版面第一階段（固定清單）先上線驗證價值 → 再做本檔的互通（watchlist 表 → Worker 讀取）。不要反過來。
