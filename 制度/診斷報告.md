# 診斷報告：KANG-agent 目前最大的三個漏洞

> 2026-07-07 由 Fable 5 寫成。這是後面所有制度檔的依據。
> 讀者：未來在這個 repo 工作的任何 Claude session（多半是 Sonnet 等級）。

## 漏洞一：最漏 token —— 主對話直接讀大檔

**現況**：`小書蟲/小書蟲-web/app.js` 約 3000 行，全部邏輯在同一檔。過去 session 很可能整檔讀進主對話，一次就吃掉大量 context；改一個小功能也把整本書搬進來。

**具體修法**（照做即可）：
1. 改 app.js 前，先用 `grep -n "函式名或關鍵字" app.js` 找行號，再用 Read 的 offset/limit 只讀該區段前後 ~80 行。**禁止無 offset 直接 Read app.js。**
2. 「不知道東西在哪」的搜尋（掃 repo、找某功能定義在哪、跨檔案調查），派 `Explore` subagent 去做，主對話只收「檔名:行號＋一句結論」。細節見 [模型調度守則.md](模型調度守則.md)。
3. 網頁查資料（API 文件、錯誤訊息）派 subagent 帶回摘要，不要把整頁 fetch 進主對話。

## 漏洞二：最容易失焦 —— CLAUDE.md 與實際專案版圖脫節

**現況**：根 CLAUDE.md 只寫小書蟲，但 repo 實際有小書蟲、短線衛兵（Python 版＋Worker 版兩套並存）、撲滿/零錢種子（子目錄是獨立 git repo、被 gitignore）、LINE主題製作、劇本。做短線衛兵時載入的全是小書蟲細節；做撲滿時甚至不知道那裡的 commit 要進另一個 repo。結果：session 花力氣重新搞懂版圖、或在錯的專案脈絡下做事。

**具體修法**：
1. 根 CLAUDE.md 改成「路由表」：一張表列出每個專案的目錄、一句話說明、詳細說明檔在哪。專案細節放各自目錄的 CLAUDE.md（Claude Code 讀到該目錄檔案時會自動載入）。
2. 每個 session 開場只需回答一個問題：「這次在做哪個專案？」然後只讀那個專案的說明檔。
3. PROJECTS.md 與根 CLAUDE.md 的路由表擇一維護（本次已把 CLAUDE.md 定為唯一真相，PROJECTS.md 保留但標註以 CLAUDE.md 為準）。

## 漏洞三：最容易出錯 —— 秘密與部署規則分散，弱模型會踩雷

**現況**：機密管理散在四處——小書蟲 config.js（gitignored、含 Claude key）、Worker secrets（wrangler secret）、撲滿子 repo 各管各的、「不要公開 Worker URL」只寫在一行註記。部署動作（`wrangler deploy`）沒有前置檢查。弱模型最典型的失敗：把 config.js 加進 git、把含 key 的 URL 貼進公開文件、或在 Python 版與 Worker 版並存的短線衛兵上改錯一套還照樣 deploy。

**具體修法**：
1. 集中一份「危險動作清單」寫進根 CLAUDE.md（commit 含 key 檔案、公開部署 URL、`wrangler deploy`、改 webhook、動撲滿子 repo 的 git），每項附「動之前必做的檢查」。
2. deploy 前固定跑 `git status` 確認沒有機密檔被追蹤，且明確說出「我要 deploy 的是哪一套（例如短線衛兵是 Worker 版，Python 版已停用）」。
3. 「完成」的定義收緊：改 UI 必須開瀏覽器（preview 工具）看過、Worker 改完必須打一次實際請求。判準見 [判斷準則.md](判斷準則.md)。

## 附帶發現（不到前三名，但值得知道）

- 短線衛兵 Python 版與 Worker 版功能重複，Worker 版已上線；Python 版是歷史包袱。已在路由中標明「以 Worker 版為準」，避免弱模型改錯邊。
- 記憶索引（MEMORY.md）裡的劇本、reading-note 工作流等內容與 repo 文件有部分重疊，維護規則見 [維護協議.md](維護協議.md)。
