# 小書蟲規劃：產品路線（儲值分工／上架／多人與黏著）

> 2026-07-07 由 Fable 5 寫成。這是判斷檔：方向與取捨在這裡，實作細節到時候照各節指引開工。
> 執行原則（與使用者議定）：判斷已寫死在檔案裡，執行由之後的 session（Sonnet 等級即可）分段做。

## 一、儲值與訂閱：接下來誰做什麼（白話版）

技術路線圖在 [規劃-儲值與訂閱.md](規劃-儲值與訂閱.md)（階段 0、1 已完成）。分工：

**使用者（KANG）要做的，都不是寫程式：**
1. **決定免費額度**：每人每月免費幾次 AI（建議 10–20 次，先大方，有量再收）。
2. **決定定價**（階段 3 前）：參考該檔估算節，最終數字你拍板。
3. **申請金流帳號**（階段 3 時）：台灣個人開發者推薦順序＝藍新 Newebpay（個人可申請）→ 綠界 → Stripe（需要外幣帳戶較麻煩）。這步只有你能做，需要身分與銀行資料。
4. **每階段驗收**：像這次一樣，實際操作一輪＋看 Supabase 資料。

**未來 session（AI）要做的：**
- 階段 2：credit_ledger 表＋Worker 扣點（需要你先把 service_role key 給 wrangler secret）＋前端餘額顯示。
- 階段 3：金流 webhook → 寫 ledger。
- 每完成一段就照維護協議寫回規劃檔。

**節奏建議**：階段 2 不急著做。現在計量已在跑，先累積 1–2 個月 `ai_usage` 真實數據，你會知道真實成本與用量分布，定價就不是猜的。**先去做第三節的黏著功能，比先做收費更重要**——沒有留下來的使用者，收費系統是蓋在沙上。

## 二、上架 App Store 的路（要走的時候再走）

**結論先講：PWA 能做到的先在 PWA 做完，上架是行銷手段不是技術升級。** 上架的真正收益是「App Store 搜尋曝光＋使用者信任感」，代價是年費 USD 99＋審核＋IAP 抽成 15–30%。

觸發條件（滿足再啟動，否則不動）：種子用戶 ≥ 30 人自然留存、或有人明確說「App Store 找不到你們所以沒裝」。

技術路徑兩條，到時擇一：
1. **WKWebView 殼包 PWA**（Capacitor 或手寫殼）：改動最小，同一份 web code。風險：Apple 對「純網頁殼」審核較嚴，需要加一兩個原生能力（推播、相機原生調用）證明 app 價值。
2. **重啟 SwiftUI 原生版**（`小書蟲/小書蟲/` 已有雛形）：體驗最好、審核最順，但等於第二個前端要長期雙維護——一人開發者慎入。

**不管走哪條**：上架版的點數/訂閱必須走 Apple IAP；PWA 版可繼續用藍新/Stripe。同一個 Supabase credit_ledger 可以同時接兩種來源（ledger 的 `來源` 欄位就是為此設計的）。

## 三、多人使用：真實連結與黏著（最重要的一節）

**定位判斷**：小書蟲的靈魂是「為自己讀的書留紀念」——它是日記，不是社群網站。錯誤方向是做成迷你版 Goodreads（追蹤/按讚/演算法牆），一人開發者養不起，也違背產品靈魂。正確方向是**「私密為主、分享為窗」**：讓「已經認識的人」透過書產生連結，而不是連結陌生人。

照這個順序做（每個都比前一個重）：

1. **公開書架升級成「活的連結」**（工程量最小、槓桿最大）：現在的匯出 HTML 是死檔案。改成每人一個公開網址（`/u/暱稱`，Supabase 已有資料，做一個唯讀公開頁），書友點進來看到的永遠是最新書架。**這一步讓每個使用者都變成入口**——放 Threads 個人簡介、貼文簽名檔。加「這本我也讀過/我想讀」一鍵回應（訪客免登入、進 Supabase 公開表），是最低成本的「真實連結」。
2. **年度回顧卡**（黏著＋自傳播）：「你今年讀了 N 本、M 句金句、讀最多的類型」做成可分享圖卡（Canvas 已有 share card 基礎）。一年觸發一次的高峰體驗，Spotify Wrapped 驗證過的模式。
3. **共讀書櫃**（真實連結的核心）：2–5 人的小圈子（家人、讀書會、情侶），圈內互相看得到書與金句、可以留一句話。**不做公開社群，只做私圈**——真實關係自帶黏著，不需要演算法。
4. **溫柔的回訪鉤子**：「一年前的今天你在讀《X》，寫下了這句」——用既有資料做記憶回放（推播或開 app 首屏）。日記型產品最強的留存機制是「過去的自己」。

**不要做的**（寫下來防止未來 session 提議）：陌生人追蹤/推薦流、留言區、排行榜、任何需要內容審核的功能——一人開發者承擔不了審核與社交風險，且會殺死「私密紀念」的安全感。

**衡量黏著只看一個數字**：週回訪率（一週內回來第二次的人 / 活躍人數）。功能上線前後比這個數，其他虛榮指標不看。

## 四、建議的執行順序（總結）

1. ✅ 計量（2026-07-07 完成）
2. ✅ 公開書架網址＋「我也讀過」（2026-07-07 完成）。實作：`/u/暱稱` 路由（wrangler assets 開 SPA fallback，hash 版 `#/u/暱稱` 也通）；資料走 `shelf_books` view（安全欄位投影，**不含** ai_summary/reading_context/筆記照片）；訪客回應進 `shelf_reactions`（RLS 只准對開啟中書架 insert，localStorage 防重複）；主人開關在 年度回顧→設定 的「🔗 公開書架連結」。已知限制：(a) 拍照上傳的封面在私有 bucket，公開頁只顯示 cover_url（Google 來源）有的封面，其餘出占位圖——升級路徑是開一個 public bucket 存封面縮圖；(b) 匿名 insert 無速率限制，種子期可接受，被灌爆再加 Turnstile
3. ✅ 年度回顧卡（本來就已存在：年度回顧頁的 share-yearly 按鈕）
4. 點數帳（等 ai_usage 數據累積 1–2 個月，2026-09 前不動）
5. 共讀書櫃（下一個大項）
6. 金流 → 訂閱 → （視訊號）App Store
